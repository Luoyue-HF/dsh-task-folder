# 04 · 配置项详解

配置写在 profile 的 `cordis.patch.yml` 里（`$DSH_HOME/profiles/<你的profile>/cordis.patch.yml`）：

```yaml
- id: dsh-task-folder
  config:
    enabled: true
    rootMode: workspace
    subdir: ''
    rootPath: ''
    autoTitle: true
    maxNameChars: 24
    autoReuse: true
    adoptOldSessions: true
```

| 配置项 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | boolean | `true` | 总开关 |
| `rootMode` | string | `workspace` | `workspace` = 任务目录根在当前工作区内；`custom` = 用 `rootPath` |
| `subdir` | string | `''` | 留空 = 任务目录直接放工作区根下；填 `产物` 则集中到 `<工作区>/产物/` |
| `rootPath` | string | `''` | `rootMode: custom` 时使用；留空回退 `~/Documents/DSH-产物` |
| `autoTitle` | boolean | `true` | 标题生成后自动把目录改成标题名 |
| `maxNameChars` | number | `24` | 任务名最大字符数（按码点计） |
| `autoReuse` | boolean | `true` | 首条消息唯一提到某已有任务名时自动切过去 |
| `adoptOldSessions` | boolean | `true` | **升级前就在用的会话也收编**——详见 [05-旧会话与升级行为](05-旧会话与升级行为.md) |

## `autoTitle` 的判定细节

- 从首条消息提取的初始名会在**标题生成后 90 秒**的时间窗口内被更好的标题名替换；超窗不再改。
- 手动 `rename` 过后，该会话永远不会被自动改名。
- 初始命名会剥离常见引导语：中文如「帮我写」「做一个」，英文如 `please`、`can you`、`make a …`、`thanks` 结尾等。

## `autoReuse` 的判定细节

只在会话第一次真正跑任务时判断一次，全部条件满足才自动切：

1. 消息里提到的任务名**唯一命中**一个已有任务目录；
2. 任务名至少 3 字符（避免「报告」「总结」这类泛词误切）。

想完全手动：设 `autoReuse: false`，改用 `task_folder action=reuse`。

## 覆盖方式

`cordis.patch.yml` 里同一 `id` 的 `config` 会被**整体替换**而不是深合并，所以你要覆盖某个配置时，把该行需要的全部键都写出来。
