# 03 · task_folder 工具用法

插件向模型注册名为 `task_folder` 的工具，模型可主动调用；你也可以在对话里直接让模型调。

## 动作一览

| action | 参数 | 作用 |
|---|---|---|
| `show` | — | 看当前任务目录、任务目录根、任务名 / 月日 |
| `list` | — | 列出全部任务目录（最多 40 个，`*` 标记当前） |
| `rename` | `name` | 改任务名，目录当场重命名；之后不再被自动改名 |
| `reuse` | `name` | 切到已有任务目录，支持完整目录名 / 任务名 / 部分匹配 |
| `new` | `name?` | 另开一个新任务目录（可带初始名） |

## 典型场景

### 换会话续做同一任务

新开一个会话，说：

> 继续做 季度汇报PPT

模型会调 `task_folder action=reuse name=季度汇报PPT`，会话 cwd 切回 `10-27_季度汇报PPT/`，后续产物继续落进同一个目录。

`autoReuse: true`（默认）时，如果会话的**第一条实质消息**唯一提到了某个已有任务名（任务名 ≥ 3 字符、且只命中一个），插件会自动切过去，不必显式说"继续做"。名字太泛（如「报告」）命中多个就放弃，退回新建目录。

### 给现在这个任务改名

> 任务名字改成 年度总结

模型调 `task_folder action=rename name=年度总结`，目录 `10-27_旧名字/` 就地重命名为 `10-27_年度总结/`。手动 rename 过的目录不会再被自动改名覆盖。

### 查看当前在哪

> 现在的任务目录是哪个

模型调 `task_folder action=show`，返回当前目录路径、任务名、月日。

## 失败行为（重要）

- **重命名失败不抛错**：文件被别的程序占用时改不了名，插件保持原名并只记一条告警。你可以稍后手动 `action=rename` 重试，绝不因为改不了名而中断任务。
- **切目录失败只告警**：`workingDirectory.set` 抛错（如目录被外部删除）不会让会话失败，回退原工作区继续跑。
- **`find` 无歧义原则**：`name` 只匹配到唯一目录才切；命中多个时返回候选列表让模型确认，不会"猜"一个。
