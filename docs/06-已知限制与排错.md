# 06 · 已知限制与排错

## 已知限制

1. **已结束的历史会话不追溯**：插件只处理启动后能观察到的会话；彻底结束的老会话不会回头归档。
2. **改名受文件锁影响**：目录里文件被别的程序占用时，重命名会跳过并记一条告警，需要稍后 `task_folder action=rename` 手动重试。
3. **任务目录不自动清理**：空目录会回收，有内容的不会；长期使用请自行归档。
4. **只服务根会话**：子代理与派生会话不另开目录，而是跟随主会话切到同一个任务目录（这是设计，不是缺陷）。0.2.2 起才有这个跟随行为；更早版本里子代理会停在工作区根。
5. **`rootMode: custom` 下没有标记文件过滤**：自定义 `rootPath` 时整个目录被视为插件独占，请别把它指向你平时的资料目录。

## 常见问题

### Q1：装了插件，会话产物还是散在工作区根？

先按顺序排查：

1. **重启了没有？** 新加入的 bundle 需要重启 DSH 才会加载。
2. **是不是老会话？** 0.2.0 及以前的版本会永久跳过「插件激活前创建」的会话——升级到 0.2.1 并确认 `adoptOldSessions: true`（默认就是）。详见 [05-旧会话与升级行为](05-旧会话与升级行为.md)。
3. **是不是子代理会话？** 子代理、派生会话不建自己的目录，它们跟随主会话。若发现子代理产物散在工作区根，说明插件版本低于 0.2.2。
4. **bundles 列表里有它吗？** 打开 `$DSH_HOME/profiles/<profile>/package.json`，确认 `dsh.profile.bundles` 数组里有 `"dsh-task-folder"`。

### Q2：用户自建的目录会被当成任务目录吗？

不会。扫描只认带 `.dsh-task-folder` 标记的目录和旧格式带序号的老目录（`2026-10-26_07_任务名`）。你手动建的 `10-27_清单` 之类没有标记，不会被误认。

### Q3：为什么出现 `xxx ~2` 目录？

同一天建了第二个同名任务目录。这不是重复，是两个不同任务的目录，靠 `~2` 区分互不覆盖。

### Q4：任务做完目录空了，被回收了？

是的，空目录（只剩标记文件也不例外）会在会话销毁、`reuse`、`new` 时被回收。如果还要用，往里面放个文件即可。

### Q5：怎么完全关掉自动行为？

```yaml
- id: dsh-task-folder
  config:
    autoTitle: false      # 不自动改成标题名
    autoReuse: false      # 不根据首条消息自动切目录
```

之后一切目录操作都由 `task_folder` 工具手动完成。
