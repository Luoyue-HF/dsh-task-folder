# 05 · 旧会话与升级行为 ⚠️

> 这篇文档专门回答一个问题：**插件装上 / 升级后，那些「插件激活之前就已经存在」的会话会怎样？**

## 三种"旧会话"，三种处理

| 类型 | 判定方式 | 插件行为 |
|---|---|---|
| **A. 升级前就在用、现在仍活跃的长会话** | `session.header.createdAt` 早于插件本次激活时刻 | **默认收编**（`adoptOldSessions: true`）：会话下一次跑任务时，照样分配 / 切到任务目录 |
| **B. 已经彻底结束的历史会话** | 不可再恢复执行 | **不做任何追溯**：不会回头给它们补建目录、搬文件 |
| **C. 子代理 / 派生会话** | `origin === 'subagent'` 或有 `parentSession` | **永远不建目录**：无论新旧，一律沿用父会话目录 |

## 为什么会专门写这篇

这是本插件 0.2.0 及以前的一个真实坑，也是「插件装了但没生效」这一误判的最常见原因：

- 旧版在插件激活时记下一个时刻 `activatedAt`，凡 `createdAt < activatedAt` 的会话**永久跳过**任务目录分配。
- 典型场景：19:13 你开了一个会话在干活，20:47 装/升级了插件并重启了 DSH。这个会话创建时间早于激活时刻，于是它**永远**不会被收编，产物继续散在工作区根——你会以为插件没生效。
- 0.2.1 起由 `adoptOldSessions` 控制，默认 `true` = 不再区别对待老会话（A 类）。

如果你确实想让老会话保持原工作目录不动：

```yaml
- id: dsh-task-folder
  config:
    adoptOldSessions: false
    # …其余配置
```

设为 `false` 就恢复 0.2.0 的行为：凡创建时间早于插件激活的老会话，一律不分配任务目录。

## 收编之后文件还在原地吗？

注意行为边界：**收编只是把会话此后新建的产物落到任务目录**。

老会话在收编之前已经散落在工作区根的文件**不会自动搬家**。想归拢的话手动处理：

1. `task_folder action=show` 确认当前任务目录；
2. 把散落的文件移进去；
3. （可选）`task_folder action=rename` 把目录名改准确。

## 与另一项规则的关系

「升级前的老会话收编」说的始终是**会话**这条线，不影响目录识别规则：判定「这是不是任务目录」靠的是 `.dsh-task-folder` 标记与旧序号格式（见 [02-任务目录规则](02-任务目录规则.md)），与会话新旧无关。
